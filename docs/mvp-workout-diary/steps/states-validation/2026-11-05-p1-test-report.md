## Подробности

### T1. Скелетон при загрузке сессии
- **Ожидалось:** во время ожидания ответа `/api/sessions/active` виден `role=status` «Загрузка тренировки», старого текста нет; после ответа — «Нет активной тренировки».
- **Получено:** так и есть; ответ API искусственно задерживался на 3 с.
- **Данные:**

```
during: { statusVisible: true, oldTextCount: 0 }
after:  { statusCount: 0, emptyVisible: true }
```

### T2. Старт тренировки на реальном API
- **Ожидалось:** экран сессии, подход 1 предзаполнен планом (вес из seed, повторы — минимум плана, RPE 3).
- **Получено:** открыт `/workouts/session`, форма «Подход 1» заполнена.
- **Данные:**

```
url: http://127.0.0.1:4200/workouts/session
weight: "60"   reps: "6"   rpe: "3"
localStorage: strive.device-id = 138E5F32-6A32-459A-BB1D-69EADA4D0EEF
```

### T3. Ошибки под полями при невалидном вводе
- **Ожидалось:** ошибка под нужным полем, `aria-invalid="true"` только у него, запросов `PUT` нет; ошибка пропадает при исправлении; при закрытии/открытии редактора ошибок нет.
- **Получено:** поведение совпало; число запросов `PUT` за весь сценарий — 0.
- **Данные:**

```
шаг 1  вес очищен       : aria-invalid weight=true reps=false rpe=false; ошибки: ["Обязательное поле"]; alert: 0
шаг 3  вес = 62.5       : aria-invalid weight=false (проверено сразу после ввода)
шаг 4а повторы очищены  : reps=true; ["Обязательное поле"]
шаг 4б повторы = 0      : reps=true; ["Не меньше 1"]
шаг 5  RPE = 6          : rpe=true;  ["Не больше 5"]
шаг 6  закрыть/открыть  : все aria-invalid=false; ошибки: []
putCount: 0
```

Замечание по наблюдению: сразу после исправления веса (шаг 3) текст старой ошибки «Обязательное поле» ещё ненадолго оставался в DOM, при повторной проверке через 1 с под весом ошибки не было (остальной остаток — ошибка RPE, значение 6 ещё не исправлено). Это задержка перерисовки, а не залипание; автотест E7 с авто-ожиданием её не ловит.

### T4. Сохранение после исправления и ошибка сервера
- **Ожидалось:** при ответе 500 — блок `alert`, ни одного `aria-invalid`, ошибок под полями нет; после снятия перехвата — подход сохранён, открыт подход 2 со значениями подхода 1; `GET /api/sessions/active` показывает результат.
- **Получено:** совпало.
- **Данные:**

```
шаг 1 (PUT -> 500): alert="Не удалось сохранить подход. Попробуйте ещё раз."
                    aria-invalid: [false,false,false]; ошибки под полями: []
шаг 2 (без перехвата): форма подхода 1 закрыта; подход 2: weight "62.50", reps "8", rpe "3"
тела PUT: {"weight":62.5,"reps":8,"rpe":3,"note":null} (x2: ответ 500 и успешный)
```

```

HTTP/1.1 200 OK
{"success":true,...,"data":{"session":{"id":58,"workout":{"name":"Тренировка A",...},
 "finishedAt":null,"results":[{"exerciseId":1,"setNumber":1,"weight":62.5,"reps":8,"rpe":3,"note":n... (обрезано)
```

Сессия завершена кнопкой «Завершить» с подтверждением; после этого `GET /api/sessions/active` вернул `{"success":true,"message":null,"data":{"session":null},"details":null}`, браузер перешёл на `/history`.
