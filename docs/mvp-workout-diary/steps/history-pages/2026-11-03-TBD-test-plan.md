# Тест-план: TBD H2 — страницы истории тренировок

**Ветка:** `h2-history-pages` (база: `main`, все изменения не закоммичены)
**Документы задачи:** `docs/mvp-workout-diary/steps/history-pages/2026-11-02-history-pages-design.md` (шаг H2 роадмапа `docs/mvp-workout-diary/`)

## Что меняется

- `GET /api/sessions/:id/summary` дополнительно отдаёт `exercises`: упражнения плана с подходами, сгруппированные по порядку плана и по номеру подхода; упражнения без подходов не включаются. Агрегаты (`exerciseCount`, `setCount`, `totalVolume`) считаются из этого же вида. Коды 404/409/400 прежние.
- Вкладка «История» (`/history`) показывает список завершённых тренировок устройства: название, дата `dd.MM.yyyy`, «N упражнений · M подходов».
- `/history/:id` показывает детали: шапку (название, дата, длительность, тоннаж) и карточки упражнений с подходами «вес × повторы», RPE и заметкой, если они заданы.
- Состояния страниц: загрузка, ошибка с повтором, пустая история, «Тренировка не найдена» (404/400/409).
- Заглушка раздела удалена; `GET /api/sessions` и `GET /api/sessions/:id` не меняются.

## Приложения к запуску

Конфига `testing.apps` нет, команды взяты из `package.json`:

| Приложение | Команда | Готовность |
|---|---|---|
| api | `npm run start:api` | порт 3000 (`/api/health`) |
| web | `npm run start:web` | порт 4200 |

Нужны тестам оба. Postgres не запускается этим прогоном: контейнер `eagleray-postgres-1` (соседний worktree) уже слушает `127.0.0.1:5435`, БД `strive` мигрирована со seed «Тренировка A/B/C».

## Предупреждения

- Тесты T1–T3 создают реальные записи (сессии и подходы) под случайным device-id в общей БД соседнего worktree; откатить нечем, записи изолированы по device-id и безвредны.
- Автотесты `e2e` (T6) сами поднимают api и web на портах 3000 и 4200 и не уживаются с уже запущенными приложениями, поэтому T6 выполняется ДО запуска приложений прогона.
- Playwright MCP: постоянный профиль `~/.cache/playwright-mcp-profile`, headless. Вход в Max не нужен.
- `NODE_TLS_REJECT_UNAUTHORIZED=0` и переопределение переменных окружения не используются.

## Тесты

### T6. Существующие e2e-спеки истории и регрессий (e2e)
- **Предусловия и данные:** порты 3000 и 4200 свободны, Postgres на 5435 доступен и мигрирован.
- **Шаги:**
  1. `npx nx run web-e2e:e2e --skip-nx-cache --output-style=static -- apps/web-e2e/src/history.spec.ts apps/web-e2e/src/history.fullstack.spec.ts apps/web-e2e/src/layout.spec.ts apps/web-e2e/src/theme.spec.ts --project=chromium`
- **Ожидаемый результат:** все выбранные спеки проходят (28 тестов): список и детали истории на моках, сквозной сценарий на реальном API, навигация (вкладка «История»), тема.
- **Побочные эффекты и уборка:** сквозной тест создаёт одну завершённую сессию под случайным device-id; серверы Playwright останавливаются сами.

### T1. Сводка завершённой тренировки с упражнениями (api)
- **Предусловия и данные:** `DEV=$(uuidgen)`; заголовок `X-Device-Id: $DEV`; seed-тренировка «Тренировка A».
- **Шаги:**
  1. `curl -s -H "X-Device-Id: $DEV" http://127.0.0.1:3000/api/workouts` — найти id «Тренировка A».
  2. `curl -s -H "X-Device-Id: $DEV" http://127.0.0.1:3000/api/workouts/<id>` — взять `exercises[0].exercise.id` (E1) и `exercises[1].exercise.id` (E2).
  3. `POST /api/sessions` с телом `{"workoutId":<id>}` — запомнить id сессии `S`.
  4. `PUT /api/sessions/S/sets/E1/1` с `{"weight":60,"reps":8,"rpe":3,"note":"Легко"}`; `PUT .../E1/2` с `{"weight":60,"reps":6}`; `PUT .../E2/1` с `{"weight":100,"reps":5}`.
  5. `POST /api/sessions/S/finish`.
  6. `curl -s -H "X-Device-Id: $DEV" http://127.0.0.1:3000/api/sessions/S/summary`.
- **Ожидаемый результат:** 200; `exercises` — два элемента в порядке плана (E1, затем E2), у E1 два подхода с `setNumber` 1 и 2 (`rpe`/`note` у первого заданы, у второго `null`), у E2 один подход; `exerciseCount` = 2, `setCount` = 3, `totalVolume` = 1340; `workoutName` = «Тренировка A».
- **Побочные эффекты и уборка:** одна завершённая сессия под случайным device-id; не откатывается.

### T2. Ошибки `/summary` (api)
- **Предусловия и данные:** сессия `S` из T1; `DEV2=$(uuidgen)`; ещё одна новая активная (незавершённая) сессия `A` под `DEV2`.
- **Шаги:**
  1. `GET /api/sessions/S/summary` с заголовком `DEV2` (чужая сессия).
  2. `GET /api/sessions/999999/summary` с `DEV`.
  3. `GET /api/sessions/abc/summary` с `DEV`.
  4. `POST /api/sessions` под `DEV2` с `{"workoutId":<id>}` → `A`; `GET /api/sessions/A/summary` с `DEV2` (не завершена).
  5. `GET /api/sessions/S/summary` без заголовка устройства.
  6. Завершить `A`: `POST /api/sessions/A/finish` с `DEV2` (уборка).
- **Ожидаемый результат:** шаг 1 — 404; шаг 2 — 404; шаг 3 — 400; шаг 4 — 409; шаг 5 — 400.
- **Побочные эффекты и уборка:** сессия `A` завершается в шаге 6; завершённая пустая сессия под `DEV2` остаётся.

### T3. Регрессия соседних ручек сессий (api)
- **Предусловия и данные:** сессия `S` и `DEV` из T1.
- **Шаги:**
  1. `GET /api/sessions` с `DEV`.
  2. `GET /api/sessions/S` с `DEV`.
- **Ожидаемый результат:** шаг 1 — 200, `data.sessions` содержит `S` с плоским `results` из 3 подходов и без полей `totalVolume`, `setCount`, `exerciseCount`, `exercises`; шаг 2 — 200, `WorkoutSession` с плоским `results` из 3 подходов, без `exercises`.
- **Побочные эффекты и уборка:** нет (только чтение).

### T4. Список и детали истории в браузере на реальном стеке (web)
- **Предусловия и данные:** приложения запущены; device-id `DEV` с завершённой сессией `S` из T1.
- **Шаги:**
  1. Открыть `http://127.0.0.1:4200/`, выполнить `localStorage.setItem('strive.device-id', '<DEV>')`.
  2. Перейти на `/history`, снять snapshot.
  3. Нажать на строку «Тренировка A», снять snapshot и прочитать сетевые запросы и сообщения консоли.
  4. Нажать «← История».
- **Ожидаемый результат:** шаг 2 — заголовок «История», одна строка «Тренировка A» с сегодняшней датой `dd.MM.yyyy` и «2 упражнения · 3 подхода»; шаг 3 — URL `/history/S`, заголовок «Тренировка A», дата, значки длительности («меньше минуты» либо «N мин») и «1 340 кг» (с неразрывными пробелами), два упражнения, подходы «60 кг × 8» (RPE 3, «Легко»), «60 кг × 6», «100 кг × 5»; единственный API-запрос деталей — `GET /api/sessions/S/summary` со статусом 200; ошибок в консоли нет; шаг 4 — URL `/history`, список виден.
- **Побочные эффекты и уборка:** значение `strive.device-id` остаётся в профиле Playwright; данные не пишутся.

### T5. Пустая история, «не найдена» и ошибка в браузере (web)
- **Предусловия и данные:** приложения запущены; новый device-id `DEV3 = uuidgen` без сессий.
- **Шаги:**
  1. Установить `strive.device-id = DEV3`, открыть `/history`, snapshot.
  2. Открыть `/history/999999`, snapshot, проверить отсутствие кнопки «Повторить» и статус запроса `/summary` (404).
  3. Открыть `/history/abc`, snapshot, статус запроса (400).
  4. Вернуть `strive.device-id = DEV` из T1, открыть `/history/A` (сессия `A` из T2 принадлежит другому устройству `DEV2`), snapshot, статус запроса (404).
- **Ожидаемый результат:** шаг 1 — «История пока пуста»; шаги 2–4 — «Тренировка не найдена» и ссылка «← История», без «Повторить»; ошибок в консоли, кроме ожидаемых 404/400 запросов, нет.
- **Побочные эффекты и уборка:** значение `strive.device-id` в профиле Playwright; вернуть его на `DEV` в конце.

## Не проверяется

- Состояние ошибки с кнопкой «Повторить» и индикатор загрузки: на реальном стеке не воспроизводятся без остановки api или задержки ответа; покрыты автотестами `history.spec.ts` в T6.
- Мобильная раскладка и свайпы: вне изменений H2.
- Max-бот и мини-приложение Max: проект их не содержит.
- Юнит-тесты, lint и build: относятся к проверке проекта, не к этому прогону (в ходе реализации зелёные).
