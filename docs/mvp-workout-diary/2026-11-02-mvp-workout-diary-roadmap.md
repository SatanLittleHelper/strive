# Роадмап: MVP дневника тренировок

## Context

**Цель.** Минимальный дневник тренировок без авторизации: пользователь смотрит заранее собранные тренировки, начинает тренировку, записывает результаты по подходам и потом видит список прошлых тренировок.

**Принятые решения.**

- **UI-кит:** Taiga UI.
- **Дизайн:** тёмный спортивный стиль с одним лаймовым акцентом, нижние вкладки Главная / Тренировки / История, ввод подходов списком с раскрывающимся редактором. Фундамент (токены, тема, каркас) реализован; составные блоки (карточка тренировки, строка подхода, пустые состояния и состояния ошибок) делаются в срезах вместе с экранами. Спека: `docs/superpowers/specs/2026-10-29-app-design-design.md` (локальный файл, в git не хранится).
- **Авторизации нет.** Пользователь определяется анонимным идентификатором устройства (генерируется на фронте, хранится в браузере, передаётся заголовком `X-Device-Id`).
- **Хранилище:** PostgreSQL через Prisma; доступ к данным только через слой репозиториев на бэкенде.
- **Каталог:** ограниченный набор упражнений и готовые тренировки (упражнения с целевыми подходами × повторами) заводятся seed-миграцией. Редактора в UI нет.
- **Запись подхода:** вес + повторы + RPE/заметка.
- **Экран тренировки:** одно упражнение на экране (свайпы, кнопки, прогресс); подход предзаполняется предыдущим подходом, целевым весом плана или прошлой тренировкой; блок «Прошлые тренировки» подставляет значения по тапу.
- **После тренировки:** только список прошедших тренировок с деталями. Без графиков прогресса и без таймера отдыха.

**Вне скоупа MVP.** Авторизация и аккаунты, создание/редактирование тренировок и упражнений, графики и аналитика, таймер отдыха, офлайн-режим, синхронизация между устройствами.

**Состояние на 2026-11-02.** Готовы фундамент, каталог и выполнение тренировки (включая доработку экрана, PR #49 и #50). Готовы также страницы истории тренировок. Осталась полировка.

**Почему роадмап.** Работа идёт вертикальными срезами (API + web), каждый можно показать и проверить отдельно, а после любого слияния приложение должно собираться и работать.

## Архитектура (целевая)

- Монорепа Nx: Angular (`apps/web`), NestJS (`apps/api`), Playwright (`apps/web-e2e`), общие контракты в `libs/api-interfaces`.
- API под префиксом `/api`, данные в PostgreSQL через Prisma и `*.repository.ts`, устройство определяется `DeviceIdGuard` по `X-Device-Id`.
- Web: standalone-компоненты, Signals, lazy routing, Taiga UI поверх Tailwind, тёмная тема, каркас с нижней навигацией.

## Сквозные риски

- Postgres добавляет инфраструктуру: бэкапы и хостинг БД на проде нужно решить отдельно (в MVP — вне скоупа, но данные не терять).
- Анонимный идентификатор в браузере теряется при очистке данных — приемлемо для MVP.
