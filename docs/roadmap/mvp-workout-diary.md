# Роадмап MVP: дневник тренировок

## Цель

Минимальный дневник тренировок без авторизации: пользователь смотрит заранее собранные тренировки, начинает тренировку, записывает результаты по подходам и потом видит список прошлых тренировок.

## Принятые решения

- **UI-кит:** Taiga UI (в проекте ещё не установлен — ставится в этапе 0).
- **Авторизации нет.** Пользователь определяется анонимным идентификатором устройства (генерируется на фронте, хранится в браузере, передаётся в заголовке запросов).
- **Хранилище:** PostgreSQL поднимается уже в MVP (локально через Docker Compose, на проде — отдельным сервисом). Доступ к данным идёт через слой репозиториев на бэкенде. Выбор ORM/клиента и схема миграций фиксируются в спеке этапа 0.
- **Каталог:** ограниченный набор упражнений и готовые тренировки (упражнения с целевыми подходами × повторами) заводятся seed-миграцией в Postgres. Редактора в UI нет.
- **Запись подхода:** вес + повторы + RPE/заметка.
- **После тренировки:** только список прошедших тренировок с деталями. Без графиков прогресса, без подсказки «в прошлый раз», без таймера отдыха.

## Вне скоупа MVP

Авторизация и аккаунты, создание/редактирование тренировок и упражнений, графики и аналитика, подсказки по прошлым результатам, таймер отдыха, офлайн-режим, синхронизация между устройствами.

## Этапы

### Этап 0. Фундамент

- Установка и настройка Taiga UI в `apps/web`, тема и базовый layout (шапка/навигация, мобильная раскладка — дневник используют в зале с телефона).
- Идентификатор анонимного устройства: генерация на фронте, хранение, передача в API; чтение на бэкенде.
- Postgres: сервис в `compose.yml`, переменные окружения в `.env.example`, проверяемая конфигурация подключения в API, механизм миграций и seed.
- Схема данных: упражнения, тренировки (с целевыми подходами × повторами), сессии тренировок, результаты подходов; привязка сессий к идентификатору устройства.
- Каркас доменных модулей API и слоя репозиториев поверх Postgres.
- Обновление проектных правил и README: в `CLAUDE.md` сейчас указано «новых баз данных нет» — это перестаёт быть правдой.
- Расширение health-проверки (`/api/health`) проверкой доступности БД и учёт Postgres в CI (сервис для тестов API и e2e).

### Этап 1. Каталог тренировок (просмотр)

- API: список тренировок, детали тренировки (упражнения, целевые подходы × повторы).
- Seed-данные: ограниченный список упражнений и несколько готовых тренировок.
- Web: страница списка тренировок и страница деталей тренировки с кнопкой «Начать».

### Этап 2. Выполнение тренировки

- API: старт сессии тренировки, получение активной сессии, запись/правка результата подхода (вес, повторы, RPE/заметка), завершение тренировки.
- Хранение сессий и результатов в Postgres, привязка к идентификатору устройства; одна активная сессия на устройство (ограничение на уровне БД).
- Web: экран активной тренировки — список упражнений, подходы по плану, ввод веса/повторов/RPE/заметки, отметка подхода выполненным, завершение.
- Возврат к незавершённой тренировке (баннер «Продолжить» на главной).

### Этап 3. История тренировок

- API: список завершённых сессий устройства, детали сессии с результатами подходов.
- Web: страница истории (дата, название, краткая сводка) и страница деталей прошедшей тренировки.

### Этап 4. Полировка MVP

- Пустые состояния, состояния загрузки и ошибок, валидация ввода (границы веса/повторов/RPE).
- E2E-сценарии Playwright: просмотр → старт → запись подходов → завершение → история.
- Обновление README (запуск с Postgres, миграции и seed).

## Порядок и зависимости

Этап 0 → этап 1 → этап 2 → этап 3 → этап 4. Этапы 1–3 вертикальные срезы (API + web), каждый можно показать и проверить отдельно.

## Риски и открытые вопросы

- Postgres добавляет инфраструктуру: бэкапы и хостинг БД на проде нужно решить отдельно (в MVP — вне скоупа, но данные не терять).
- Тесты API с реальной БД: нужен способ изоляции (отдельная тестовая БД или транзакции), решается в спеке этапа 0.
- Анонимный идентификатор в браузере теряется при очистке данных — приемлемо для MVP.
- Совместимость Taiga UI с Angular 22 (zoneless, OnPush) проверить при установке в этапе 0.
