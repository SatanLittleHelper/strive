# Роадмап: замечания к тренировке, истории и главной

## Context

**Проблема.** По результатам ручного прогона набралось 13 замечаний к экрану тренировки, истории и главной (список — на скриншоте в сессии Codex «Обновление ai-dev-kit»). Исправления затрагивают одни и те же компоненты (`active-session`, `exercise-step`, `exercise-history`, `set-editor`), поэтому один большой план получился слишком объёмным и трудно проверяемым.

**Текущее состояние.** Экран `/workouts/session` сохраняет подходы, история показывает прошлые тренировки, главная показывает только баннер «Продолжить». Серверный контракт уже принимает вес 0; данные и схема БД не меняются.

**Целевое состояние.**
- Прогресс тренировки учитывает частично выполненные упражнения.
- В истории последний подход сверху; отдельные состояния загрузки, ошибки и «нет выполнений».
- Нажатие на запись подставляет вес, повторы и RPE в форму и не затирает заметку; правка сегодняшнего подхода — свайпом и кнопкой.
- Автопереход после последнего планового подхода обычного упражнения — через 3 секунды с отменой; в суперсете без задержки.
- Пустой вес сохраняется как 0.
- После завершения открываются детали именно этой тренировки (`/history/:id`).
- На главной есть карточка следующей тренировки.
- Мобильная вёрстка: меньшие кольца и заголовок, цвета RPE, индикатор суперсета.

**Жёсткие ограничения.**
- Согласованные решения и сценарии: `docs/superpowers/specs/2026-11-17-workout-feedback-design.md`; тесты: `docs/superpowers/plans/2026-11-17-workout-feedback-tests.md` (44 идентификатора, каждый ровно в одном шаге ниже).
- Визуальные шаги (`V1`–`V3`) не начинаются, пока пользователь не утвердил макеты (`V0`).
- Серверный контракт, схема БД и миграции не меняются.
- Только тёмная тема, компоненты Taiga UI в приоритете, юнит-тесты компонентов не пишутся (`CLAUDE.md`).
- Следующая тренировка — следующая в каталоге после последней завершённой; нет истории, последней нет в каталоге или она последняя — первая; пустой каталог — карточки нет.

**Почему роадмап, а не один план.** Часть шагов независима (вес, главная, завершение), часть упирается в согласование макетов; шаги можно выпускать по одному, и после каждого приложение собирается и работает.

**Допущения оценки.** Один разработчик, знающий стек; «агент» — календарное время с ревью человека. Оценки грубые.

## Архитектура (целевая)

- Чистые helpers: доля выполнения упражнения/тренировки, порядок подходов, выбор следующей тренировки.
- Статус истории (`loading | error | loaded`) пробрасывается из `active-session` в `exercise-history`.
- Подстановка из истории — отдельный запрос в `set-editor`, меняющий только вес, повторы и RPE; режим правки — сегодняшняя запись + кнопка «Отменить правку».
- Автопереход — таймер на RxJS `interval` с отменой по `Subject` и `DestroyRef`.
- Карточка следующей тренировки — самостоятельный компонент `app-next-workout` на главной.

## Сквозные риски

- Шаги `H2`, `R1`, `R2`, `T1` правят одни и те же компоненты: выпускать строго по зависимостям или с ребейзом, иначе конфликты в `exercise-history` и `active-session`.
- Существующие e2e-тесты, поведение которых намеренно меняется (порядок подходов, правка через кнопку, задержка перехода, URL после завершения, необязательный вес), обновляются в том шаге, где меняется поведение.
- Существующий e2e `[E7]` («метки суперсета над упражнением нет») проверяет сессию без суперсетов и остаётся валидным при появлении индикатора в `V1`.
