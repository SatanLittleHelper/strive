# Шаг R2 — правка сегодняшнего подхода свайпом: дизайн

Шаг роадмапа `workout-feedback`. Исходная спека `2026-11-17-workout-feedback-design.md` и тест-план утеряны, поэтому требования восстановлены из описания шага в роадмапе и из кода R1 (коммит `84ae409`). Идентификаторы `E2`, `E17`, `E18`, `E19` из роадмапа закрепятся за сценариями ниже в тест-плане шага.

## Контекст

R1 развёл два действия над записью в истории:

- нажатие подставляет вес, повторы и RPE в форму, заметку не трогает (`E3`, `E20`);
- правку по нажатию R1 отключил: у `ExerciseHistoryComponent` нет `editSet`, а `ExerciseStepComponent.selectSet` остаётся без эмиттера.

В `ActiveSessionComponent` уже есть `selectedSet` и `getEditorSet`, которые умеют режим `edit`. `SetEditorComponent` умеет сохранять сохранённый подход под тем же `setNumber`. Не хватает жеста, который выбирает подход, и выхода из правки.

## Требования

1. Свайп влево по строке подхода в группе «Сегодня» открывает этот подход на правку.
2. В режиме правки форма заполнена сохранёнными значениями подхода (включая заметку), главная кнопка называется «Сохранить изменения», в заголовке подхода видно «правка N».
3. Сохранение правки отправляет тот же номер подхода, дубликата не создаётся. После сохранения форма возвращается к первому несохранённому подходу; если упражнение выполнено полностью, показывается карточка «Упражнение выполнено».
4. В режиме правки есть кнопка «Отменить правку». Она закрывает правку без сохранения, форма возвращается к первому несохранённому подходу.
5. Выбранный для правки подход не переходит на другое упражнение или на соседнее вхождение того же упражнения (смена упражнения сбрасывает выбор).
6. Выбор подхода на правку сбрасывает запрос подстановки из истории, поэтому прежняя подстановка не затирает значения правки.
7. Нажатие на строки «Сегодня» и прошлых тренировок по-прежнему только подставляет значения (`E3`, `E20`).
8. Свайп по строке не переключает упражнения, а горизонтальный свайп мимо строк переключает, как раньше.
9. При `disabled` (идёт сохранение, диалог, завершение) свайп ничего не делает.

Не меняются: API, схема БД, режим `extra` («Ещё подход» — шаг A1), история прошлых тренировок (строки без жеста правки).

## Решение

Жест правки — свайп влево по строке «Сегодня», кнопки правки на строке нет (решение пользователя). Основание: нажатие занято подстановкой, а переключение упражнений использует тот же горизонтальный свайп на уровне экрана, поэтому его нужно перехватывать на строке.

### Компоненты

- `ExerciseHistoryComponent`: на каждой строке «Сегодня» директива `tuiSwipe`, при `direction === 'left'` и `!disabled()` эмитит `editSet` с номером подхода. Строка помечается атрибутом `data-set-row`, по которому экран отличает свайп по строке.
- `ExerciseStepComponent`: `onEditSet(setNumber)` сбрасывает `fillRequest` и эмитит `selectSet`; `cancelEdit` эмитит новый `cancelEdit`. Кнопка «Отменить правку» (`tuiButton`, `appearance="secondary"`) показывается под формой только при `editorSet().mode === 'edit'`.
- `ActiveSessionComponent`: `(cancelEdit)` сбрасывает `selectedSet` в `null`. `onSwipe` игнорирует свайп, начатый на `[data-set-row]`, по аналогии с проверкой `input, textarea`. Сброс `selectedSet` при смене упражнения уже есть (`linkedSignal` по `currentExercise().id`) и закрывает требование 5.

### Поток данных

Свайп по строке → `editSet` (history) → `onEditSet` (step: сброс `fillRequest`, `selectSet`) → `selectedSet.set(n)` → `getEditorSet` возвращает `edit` → форма берёт сохранённый результат. Сохранение → `onSaved` сбрасывает `selectedSet`. Отмена → `selectedSet.set(null)`.

### Ошибки

Ошибка сохранения правки обрабатывается так же, как у обычного подхода: сообщение в форме, правка остаётся открытой.

## Подходы

1. **Свайп на строке с перехватом на экране** (выбрано) — минимальные изменения, использует имеющиеся `TuiSwipe`, `selectedSet`, `getEditorSet`.
2. Долгое нажатие на строку — отвергнуто: нет готовой директивы, хуже обнаруживается, выбор пользователя иной.
3. Отдельный режим «Править» переключателем над группой — отвергнуто: лишнее состояние и экран.

## Риски

- Свайп не имеет альтернативы с клавиатуры или мышью. Решение принято намеренно; если понадобится, кнопку можно добавить отдельным шагом.
- Правка проверяется Playwright только в проекте `chromium-touch` (свайп-кейсы); десктопный проект эти кейсы пропускает.

## Тестирование

Юнит-тесты компонентов не пишутся (`CLAUDE.md`), поведение проверяет Playwright. Шесть тестов с `test.fixme` «(вернуть в R2)» возвращаются в работу, где нужно, жест нажатия заменяется свайпом (`support/swipe.ts`) и тег `@touch`:

- `session.history.spec.ts`: открытие правки, сохранение с тем же номером, возврат к первому несохранённому, карточка «Упражнение выполнено» (4);
- `session.duplicate.spec.ts`: `[E10]` выбор не переходит на соседнее вхождение (1);
- `session.fullstack.spec.ts`: правка через «Сегодня» без дубликата (1).

Новые сценарии: «Отменить правку» закрывает правку без запроса на сервер; свайп по строке не переключает упражнение; нажатие по-прежнему только подставляет.
